# Contributors

## Structure

- When making stdlibs make sure to add this comment as the first line
```nasm
; {LIB NAME} Made by: {Your GitHub profile link}
```
- When making changes to the interpreter or other python files add necessary comments explaining your changes
- When making python files add this comment as first line
```nasm
# {FILE NAME} Made by: {Your GitHub profile link}
```

## PR

- When making stdlib, explain your library, and what it does
- When making changes to existing file, explain what was changed and why
- When adding new files, explain what it does, and why you think it's a good addition

## Issues
- State your issue 
- Explain your issue with detail
- If possible show screenshots or merely just the output
- If you too are a programmer perhaps add prints around and log some stuff then paste it with the outputs

## Code of Conduct

- Do not add any gore/adult content (KEEP IT SFW!)
- Make your code somewhat readable and with good comments explaining design decisions, if possible journal your thought process (wow)
- Your PR may not get accepted immediately, for I wanna actually understand what it does and how it does that you know (If ever I revert your PR just forgive me, im indecisive sometimes XD)

## Possible contributions

- Stdlibs
- Expand the ISA (Tho keep the instructions simple so that it has a low level feel still)
- Make your own user made libs, if it isn't turned into a stdlib, you can always just upload it on GitHub and other users who want it can install it!
